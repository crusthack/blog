# 관리자 클라우드

사이트 관리의 **관리자 클라우드**(`/admin#drive`)에서 사용하는 서버 기반 비공개 파일 보관함입니다. 외부 S3·Google Drive 계정 연결이나 PC 전체 파일 탐색 기능은 아닙니다.

## 사용

- 폴더 생성, 하위 폴더 탐색, 현재 폴더 이름 검색, 50개 단위 목록.
- 여러 파일을 차례로 업로드하고 완료 개수를 표시합니다. 실패 이전에 성공한 파일은 보관되며, 실패 원인을 표시합니다.
- 파일별 다운로드, 이름 변경과 폴더 이동. 중복 이름은 덮어쓰지 않습니다.
- 삭제는 휴지통으로 이동합니다. 폴더는 비어 있어야 삭제할 수 있습니다.
- 휴지통에서 이름과 위치를 지정하여 복원하거나 확인 후 영구 삭제할 수 있습니다.
- 파일당 25MiB, 휴지통 포함 총 5GiB, 전체 항목 10,000개·폴더 1,000개 제한.

## 저장과 권한

- 모든 `/api/admin/drive` API는 Owner 권한을 확인합니다. 일반 회원과 비로그인 사용자는 접근할 수 없습니다.
- 원본 파일 이름은 DB에만 저장하고 실제 파일은 GUID 이름으로 저장합니다. 폴더는 DB상의 논리 구조입니다.
- 서버 파일 경로를 입력받지 않습니다. 경로 구분자·제어 문자를 거절하고 폴더 순환 이동을 차단합니다.
- 파일 응답은 no-store, application/octet-stream, attachment, nosniff로 전달합니다. 공개 공유·브라우저 내 실행·미리보기는 제공하지 않습니다.
- 기존 동일 출처 쓰기 요청 검사와 요청 제한을 사용합니다. 수정·삭제는 revision으로 오래된 화면의 변경을 거절합니다.
- SQLite 쓰기 잠금 안에서 폴더·중복 이름·용량 조건을 검사하고 변경합니다. 업로드 실패 시 작성한 파일을 정리합니다.
- 폴더 생성·업로드·변경·삭제·복원·영구 삭제는 감사 기록에 남깁니다.

## 운영

기본 저장 위치는 `runtime/private-drive`입니다. 기본 Docker 배포의 `blog_runtime` 볼륨과 `backup-runtime.sh` 백업에 DB와 함께 포함됩니다. 배포 시 `AddAdminDrive` 마이그레이션이 자동 적용됩니다.

`BLOG_DriveStorage__StoragePath`로 저장 경로를 변경할 수 있습니다. 변경 시 기존 파일을 함께 이전해야 하며 runtime 외부 경로는 별도 영구 볼륨과 백업이 필요합니다. 공개 정적 파일 디렉터리를 저장 경로로 사용하지 마세요.

영구 삭제 후 파일시스템 정리에 실패하면 오류 로그에 파일 GUID가 기록됩니다. 해당 파일은 더 이상 API로 조회·다운로드되지 않으며 운영자가 저장 디렉터리에서 정리해야 합니다. 용량 표시는 DB 기준으로, 외부에서 복사한 파일이나 이러한 잔여 파일은 포함하지 않습니다.
