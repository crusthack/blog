# 로드맵 반영 현황

기준: 제공받은 `blog-improvement-roadmap.mdx`, `NEXT_AGENT_HANDOFF.md`와 기존 `blog-private` 구현. 현재 Next.js + ASP.NET Core + SQLite 구조에 맞춰 적용했다.

## 완료 범위

| 영역 | 반영 내용 |
| --- | --- |
| 명시적 저장 | 글과 필기는 저장 버튼으로만 보관. 초안·자동 저장·자동 병합 없음 |
| 편집·읽기 | 편집/나란히/미리보기, Markdown 도구, 미저장 안내, 목록 정렬, 카테고리 주소와 계층형 TOC |
| 슬라이드 | 자동/수동 분할, 제목/필기 슬라이드, 목차, 전체화면, 테마, 확대, 인쇄, 단축키 |
| 필기 | 메모 이동/크기/접기, 펜/지우개, 실행 취소/다시 실행, IndexedDB 명시적 저장·재열기 복구 |
| 기기 간 저장 | 계정별 서버 저장/불러오기, 버전 충돌 거절, 덮어쓰기 확인, 용량 제한, 내 저장 내역 관리 |
| 삭제 복구 | 휴지통, 첨부 보존, 비공개 복원, 번호 입력 후 영구 삭제, 영구 삭제한 글 번호 재사용 방지 |
| 이미지 수명 관리 | 기존 업로드 실패 롤백에 더해 DB/실제 파일 비교, 누락·크기 불일치·고아 후보 조회 |
| 커뮤니티 | 초대 회원, 작성자 권한, 댓글·답글, 북마크, 신고·정지·감사 기록, 검색·필터·페이지 탐색 |
| 통합 관리 | `/admin` 현황판에서 글·카테고리·회원·신고·초대·설정·휴지통·저장소·상태 관리 |
| 관리자 클라우드 | Owner 전용 폴더·파일 보관, 이동·이름 변경·휴지통·복원과 용량 제한 |
| 로컬 게임 | `/game`의 서바이버, BLOCK RUN, 숫자 야구, 지뢰찾기. 서버 저장 없이 브라우저에서 실행 |

## 관리 화면

- `/admin`: Owner용 통합 관리 화면. 해시 주소로 각 관리 도구를 직접 열 수 있다.
- `/posts/manage`: 게시글 목록 및 휴지통/파일 점검으로 이동.
- `/posts/trash`: Owner만 조회·복원·영구 삭제 가능. 휴지통에서는 본문, 첨부, 서버 필기 열람을 차단한다. 복원은 항상 비공개이며 이전 코드 인증도 무효화한다.
- `/storage`: Owner용 읽기 전용 점검. 최근 1시간 이내의 미등록 파일은 업로드 중일 가능성이 있어 별도 집계한다. 휴지통 글의 첨부는 등록된 파일로 취급한다. 점검은 파일을 삭제하지 않는다.
- `/workspaces`: 로그인한 사용자의 서버 필기 관리. 글을 열람할 수 없으면 제목을 숨기고 본인 저장 데이터 정리는 허용한다. 영구 삭제된 글의 서버 필기는 함께 제거한다.

영구 삭제 중 파일 시스템 삭제가 실패하면 서버 로그에 남고 파일 점검에서 고아 후보로 확인할 수 있다. DB 삭제와 파일 삭제를 원자적으로 묶을 수 없으므로 점검은 자동 정리로 확장하지 않았다.

## DB 및 배포

`20260916061040_AddTrashAndSlideWorkspaces`는 기존 글을 유지하며 삭제 시각, 서버 필기
테이블, 글 번호 발급 카운터를 추가한다. 이후 커뮤니티, 글 우선순위와 관리자
클라우드 migration도 같은 자동 적용 절차를 사용한다. 글 번호 카운터는 기존 최대
글 번호에서 시작한다.

배포 스크립트는 전환 전에 런타임(DB·첨부·Data Protection 키·관리자 클라우드)을
백업한다. 새 스키마로 운영한 뒤 이전 앱으로 롤백할 때는 새 데이터의 보존 범위를
먼저 확인해야 한다. migration은 격리된 임시 DB와 통합 테스트로 검증한다.

## 남은 항목

- 계층형 카테고리 및 카테고리 이동 UX.
- 이메일 확인·계정 복구·MFA/SSO와 조직 단위 권한.
- 브라우저 로컬 필기 전체 관리, 이전 본문 버전 필기 마이그레이션.
- 첨부 및 관리자 클라우드의 파일 고아 정리, 외부 백업과 복원 리허설.
- 원문/MDX 즉석 편집, 고급 인쇄 레이아웃.
- 실제 브라우저 기반 주요 사용자 흐름 E2E와 모바일 회귀 테스트.

서버 필기는 계정당 최대 100개, 작업당 5MB이며 별도 버전 이력은 보관하지 않는다.
커뮤니티 구현 상세는 [커뮤니티 구현 현황](COMMUNITY_EVOLUTION.md), 남은 이식 항목은
[기능 이식 현황과 로드맵](FEATURE_MIGRATION_ROADMAP.md)을 참고한다.

## 검증

- 프런트엔드 lint·프로덕션 build와 Node 테스트 전체.
- 백엔드 통합 테스트 전체: 권한·업로드 회귀, 휴지통/복원, 번호 재사용 방지,
  계정 격리, 코드 인증, 저장 충돌, 커뮤니티, 관리자 클라우드와 파일 점검.
- 실제 API와 임시 SQLite DB로 브라우저에서 서버 필기 저장/불러오기, 영구 삭제 확인 보호, 비공개 복원을 확인.
