# 슬라이드·메모·드로잉

## 참고 분석

- `blog-private/components/post/SlideDeck.tsx`, `SlideContent.tsx`: 제목 슬라이드, 자동/수동 분할, 목차, 전체화면, 테마, 확대, 인쇄, 키보드 이동.
- `SlideTextMemo.tsx`: 여러 텍스트 메모의 이동·크기 조절·접기·삭제.
- `SlideDrawingCanvas.tsx`, `SlideDrawingToolbar.tsx`: 펜 색상·굵기, 지우개, 그림 지우기, 별도 필기 슬라이드.
- `blog-private/lib/post/slides.ts`: 요소별 가중치와 제목 기반 자동 분할, `---` 수동 분할.
- 제공받은 `blog-improvement-roadmap.mdx`, `NEXT_AGENT_HANDOFF.md`: 명시적 Save, IndexedDB 재열기 복구, 자동 저장 금지, 사용자·포스트 분리, 저장 실패 안내, 권한 경계와 인쇄 품질.

## 현재 구현

포스트 상단 **슬라이드로 보기**를 누르거나 `/posts/{category}/{number}/slides`로 접속한다. 본문과 같은 API에서 접근 권한을 확인하므로 비공개·코드 보호 글도 동일한 열람 조건이 적용된다. 기존 카테고리 주소는 현재 주소로 바뀌며 슬라이드 번호 `#slide=N`을 유지한다.

자동 모드는 제목과 본문 분량에 따라 나누고 수동 모드는 Markdown 수평선 `---`에서 나눈다. 코드·표는 통째로 유지하며 코드 안의 구분선과 Setext 제목을 잘못 분할하지 않는다. 긴 단일 코드/표는 본문 영역에서 스크롤할 수 있다. 필기는 슬라이드 좌표에 고정되므로 긴 본문은 원하는 위치까지 스크롤한 후 그린다.

메모와 그림은 **원문을 수정하지 않는 개인 작업 공간**이다. 필기 슬라이드도 원문과 별도로 추가된다. 메모는 드래그 또는 제목 표시줄의 방향키로 이동하고, 오른쪽 아래 크기 조절 버튼의 드래그·방향키로 크기를 바꾼다. 펜은 마우스·터치·스타일러스 Pointer Events를 사용한다. 지우개는 선택한 선 전체를 지운다. 삭제·그림 지우기·필기 슬라이드 삭제는 실행 취소로 복구할 수 있다(최대 60단계).

기본 화면은 이전 private 블로그처럼 상단 도구줄, 배경과 이어지는 본문, 하단 이동·다음 제목 안내로 구성한다. 메모·그리기는 상단에서 바로 실행하고, **더보기**에서 저장·분할·테마·확대·인쇄·단축키를 연다. 더보기 옆 점은 저장하지 않은 변경을 뜻한다. 목차는 본문 크기를 바꾸지 않는 겹침 패널로 열린다.

## 저장 정책

- **작업 저장** 또는 **Ctrl/⌘+S**만 IndexedDB에 쓴다. 수정 직후의 자동 저장은 없다.
- 저장 완료 뒤 같은 브라우저에서 다시 열면 메모·좌표·크기·접힘·선·필기 슬라이드를 복원한다.
- 키는 사용자 ID(비로그인은 visitor), 글 번호, 본문 SHA-256, 분할 방식으로 구성한다. 글/사용자/본문 버전 간에 필기가 섞이지 않는다. 본문이 바뀌면 새 공간을 사용하며 이전 공간의 데이터는 보존된다.
- 저장 내용은 필기 데이터이며 원문이나 접근 코드는 저장하지 않는다. 비로그인 방문자의 작업은 같은 브라우저의 방문자 공간을 공유한다.
- 여러 탭의 변경이 충돌하면 오래된 탭의 저장을 거절한다. 성공한 트랜잭션 이후에만 저장 완료로 표시한다.
- 5MB 저장 한도, 슬라이드별 메모 20개/선 500개, 선별 점 4,000개, 필기 슬라이드 100개 제한.
- 저장소가 차단되면 경고하며 메모리 작업만 가능하다. 저장하지 않고 종료하면 변경이 사라진다. 종료/분할 전환/일반 링크 이동에는 저장 확인을 표시하고 탭 닫기·새로고침에는 브라우저 확인을 사용한다. 브라우저 뒤로/앞으로 이동까지 가로채지는 않는다.
- 로그인한 사용자는 **서버에 저장 / 서버에서 불러오기**로 기기 간 필기를 옮길 수 있다. 서버 저장도 명시적 버튼으로만 실행한다. 원문/MDX 즉석 편집은 포함하지 않는다.

### 서버 저장

- 서버 확인은 저장 내역의 존재를 확인할 뿐 현재 필기를 자동으로 덮어쓰지 않는다. 불러오기와 기존 서버 필기 덮어쓰기는 확인창을 거친다.
- 사용자·글·본문 SHA-256·분할 방식으로 분리하며 요청마다 글의 열람 권한을 확인한다. 코드 보호 글은 유효한 접근 코드 인증이 필요하다.
- 저장 버전을 비교해 다른 탭/기기의 변경과 충돌하면 거절한다. 최신 서버 상태를 확인한 뒤 사용자가 다시 저장해야 한다. 자동 병합하지 않는다.
- 서버 불러오기 중 새로 작성한 필기가 있으면 화면을 덮어쓰지 않는다. 연결 실패는 재시도할 수 있고 브라우저 필기는 유지한다.
- 작업당 5MB, 계정당 100개 제한. `/workspaces`에서 본인 서버 저장 내역을 확인하고 삭제한다. 본문 변경 이전의 저장 내역도 정리할 수 있다.
- 브라우저 저장과 서버 저장은 별개다. 서버에서 불러온 작업을 브라우저에도 보관하려면 **작업 저장**을 누른다.

## 단축키

| 키 | 동작 |
| --- | --- |
| ← / →, Space | 이전/다음 (그리기 중 ←/→는 색상 전환, Space는 이동하지 않음) |
| PageUp / PageDown | 그리기 중에도 이전/다음 |
| Home / End | 처음/마지막 |
| J / K | 이전/다음 큰 제목 |
| F / T / ? | 전체화면 / 목차 / 도움말 |
| M / N / D | 메모 / 필기 슬라이드 / 그리기 모드 |
| E / C | 지우개 전환 / 현재 그림 지우기 |
| 1–6 / ↑↓ | 펜 색상 / 굵기 |
| Ctrl/⌘+Z, Ctrl/⌘+Shift+Z 또는 Ctrl+Y | 실행 취소 / 다시 실행 |
| Ctrl/⌘+S | 작업 저장 (입력 중에도 동작) |
| P | 인쇄/PDF |
| Esc | 패널 닫기 → 그리기 해제 → 전체화면 종료 → 본문 |

입력창과 IME 조합 중에는 일반 슬라이드 단축키를 무시한다. 메모 입력창의 Ctrl+Z는 텍스트 편집 기능을 그대로 사용한다.

## 인쇄

모든 슬라이드를 출력하며 필기 포함 여부를 선택할 수 있다. 긴 코드·표는 줄바꿈하며 본문 다음에 그림과 메모를 함께 출력한다. 화면에서 접힌 메모도 텍스트가 출력된다. 원문 글의 읽기 화면과 동일하게 브라우저 인쇄/PDF를 사용한다.

## 검증

`npm run test:frontend`: Markdown 분할, 필기 슬라이드 계층과 실행 취소, 단축키 충돌, 명시적 저장, 저장 격리, 다중 탭 충돌, 용량 제한. 브라우저에서 슬라이드 이동·메모·드로잉·저장·재열기·모바일·보호글을 확인한다.
