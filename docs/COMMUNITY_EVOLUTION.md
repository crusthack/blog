# 마크다운 커뮤니티 구현 현황과 고도화 계획

## 원칙

기존 테마·리스트 게시판·카테고리 주소·안전한 Markdown 렌더링을 유지한다. 초안/자동 저장을 도입하지 않는다. 단일 Owner 운영 권한과 회원의 자기 글 편집 권한을 구분한다.

## 구현 완료 범위

1. 초대 코드 기반 회원 가입, 계정 정지 및 즉시 요청 차단.
2. 회원 글 작성, 본인 글/첨부 수정, 운영자 휴지통 관리. 비공개는 작성자와 운영자만 접근.
3. Markdown 댓글과 한 단계 답글, 수정/삭제, 북마크와 개인 목록.
4. 신고 접수, 운영자 처리 및 감사 기록.
5. 서버 검색/필터/정렬/페이지 나누기, 글 편집 버전 충돌 검출.
6. 권한·경합·입력·보호 글·데이터 보존에 대한 통합 테스트와 화면 검증.

## 후속 운영 확장

- 이메일 확인·계정 복구·MFA/SSO 및 조직별 권한 정책.
- PostgreSQL 전환, 객체 저장소, 외부 검색 인덱스와 작업 큐.
- 중앙 로그/지표/알림, 백업 복원 리허설, 부하 시험에 근거한 SLO.
- 스팸 판정·신고 이의 제기·데이터 보존 및 삭제 정책.

위 운영 확장까지 완료한 엔터프라이즈 인증 제품을 뜻하지 않는다. 현재 배포 형태는 SQLite 단일 서버이며 초대 기반으로 참여 규모를 통제한다.

## 구현 결과와 사용 흐름

위 구현 범위 1~6을 반영했다. 기존 테마/CSS를 재사용하며 카드형으로 바꾸지 않았다.

- **사이트 관리**(`/admin`)의 신고·회원·초대·감사 기록 도구에서 운영한다.
  기존 `/community/manage` 주소도 호환 화면으로 유지한다.
- 초대는 7일 유효한 일회용 코드이며 DB에는 SHA-256 해시만 저장한다. 원문은 발급 시에만 표시한다. 사용하지 않은 초대는 회수할 수 있다. 가입 실패 시 초대 사용을 롤백한다.
- `/join`에서 가입 후 로그인한다. 일반 회원은 글 작성·본인 글/첨부 편집·댓글·북마크·개인 슬라이드 작업을 사용할 수 있다.
- 공개/비공개/접근 코드 정책을 그대로 사용한다. 비공개 글은 작성자와 Owner만 열람한다. 댓글·필기·첨부도 글 권한을 확인한다.
- 마크다운 댓글과 한 단계 답글, 미리보기, 작성자 수정, 작성자/운영자 삭제. 삭제 댓글은 빈 자리로 남고 답글은 보존한다. 글 영구 삭제 시 댓글·북마크·신고도 함께 제거된다.
- 댓글 제목에는 본문 목차 ID를 부여하지 않아 본문 내비게이션과 충돌하지 않는다. HTML/MDX 실행을 활성화하지 않았다.
- `/bookmarks`: 회원별 북마크 목록. 비공개 전환·휴지통 처리로 열람 권한이 사라진 글은 목록에 나오지 않는다.
- 신고는 같은 대상에 처리 중인 중복 접수를 막는다. 운영자는 사유를 남겨 종결하거나 댓글 삭제/게시글 휴지통 이동을 함께 수행한다.
- 정지 계정은 로그인 및 기존 세션 요청을 즉시 거절하고, 거절된 세션의 쿠키를 제거한다. Owner는 정지할 수 없다.
- 감사 기록에는 글 생성/수정/휴지통/복원/영구 삭제, 가입/정지, 초대 발급/회수, 댓글 삭제, 신고 처리의 실행자와 대상·시각을 기록한다. 비밀번호·초대 원문·접근 코드·본문은 기록하지 않는다. 별도 외부 보관/변조 방지 저장소는 후속 단계다.

## 성능 및 API 계약

- `/api/posts/directory`: 20개씩 조회. 제목·설명 검색, 카테고리/공개 범위/본인 글/북마크 필터, 최신/오래된/수정일/제목 정렬. 동일 값에서는 글 번호로 순서를 고정한다.
- 이전 `/api/posts` 배열 API는 `page` 기준 100개로 제한한다. 기존 클라이언트의 전체 수집은 페이지 순회 또는 directory API로 전환해야 한다.
- 글 수정은 `expectedRevision`으로 이전 버전을 전달한다. 서버 버전과 다르면 409이며 브라우저의 입력은 지우지 않는다. 댓글 수정도 버전을 비교한다.
- 댓글 30개, 운영 목록 30개씩 반환한다. 댓글은 글당 10,000개, 내용 10,000자, 신고/처리 사유 1,000자로 제한한다.
- 가입·로그인과 커뮤니티 쓰기 요청에 IP 기준 속도 제한을 적용한다. 같은 프록시/NAT 사용자의 한도 공유와 다중 서버 분산 제한은 후속 운영 설계 대상이다.
- 브라우저의 cross-site/same-site 변경 요청을 Fetch Metadata로 차단하고 기존 HttpOnly/SameSite 쿠키를 유지한다. 헤더가 없는 비브라우저 API 클라이언트까지 차단하지는 않는다.

## 배포와 검증

`20260916064713_AddCommunityFoundation` 마이그레이션으로 기존 사용자/글을 유지하면서
회원 상태, 글 버전, 커뮤니티 테이블과 인덱스를 추가한다. 배포 스크립트는 전환 전
런타임을 백업하며 Backend 시작 시 적용되지 않은 migration을 자동 적용한다.

검증은 임시 SQLite DB에서 실행한다. 통합 테스트는 초대 만료/회수/중복 사용/가입 실패 롤백, 작성자 권한, 편집 충돌, 코드 보호 댓글, 북마크 격리, 신고 처리, 영구 삭제 연쇄 처리, 정지 세션, 검색/페이지 경계를 다룬다. 브라우저에서 회원 글 게시, 댓글 미리보기/등록, 북마크, 신고 접수와 운영자 처리/회원 목록/감사 기록을 확인한다.

현재 `main`의 백엔드 통합 테스트와 프런트엔드 테스트 전체를 실행한다.
lint·프로덕션 build·포맷 검사 및 DB 모델/migration 일치 여부를 함께 확인한다.
커뮤니티 회귀 항목에는 초대, 작성자 권한, 댓글·북마크·신고·정지와 검색/페이지
경계가 포함된다. 정확한 테스트 수는 실행 결과를 기준으로 한다.
